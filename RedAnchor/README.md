# RedAnchor Shell

Полноэкранная консольная оболочка для ОС RedAnchor (Qt 6 / QML), которая работает вместо GNOME.

## Первичная настройка

1. **Приветствие.** Пульсирующий логотип, затем по центру «Добро пожаловать в RedAnchor!
   Давайте всё настроим для комфортной игры».
2. **Контроллер.** Подключите DualSense кабелем и нажмите PS. Сопряжение по Bluetooth
   выполняется автоматически через кабель. Затем экран просит отключить кабель и нажать PS;
   когда контроллер действительно подключится по Bluetooth, подтвердите кнопкой ✕.
   Если Bluetooth-модуля нет или сопряжение не удалось, контроллер работает по кабелю.
3. **Язык.** Пока доступен только русский.
4. **Сеть.** Только настоящие данные NetworkManager. Есть Wi-Fi модуль — показываются найденные
   сети. Нет — экран предлагает подключить кабель Ethernet (и показывает его состояние)
   или пропустить шаг.
5. **Проверка обновлений.** Оболочка проверяет компоненты для игр (графический драйвер,
   Vulkan, Proton) и при подключении к интернету сразу устанавливает недостающие.
   Продолжить можно в любой момент — установка доделается в фоне.
6. **Аккаунт.** Вход пока фиктивный: проверяется только формат почты и пароля. Если вход
   пропустить, нужно ввести никнейм — создаётся локальная учётная запись.
7. **Финальный экран**, затем главный экран.

Прогресс и учётные записи сохраняются в `~/.config/RedAnchor/RedAnchor Shell.conf`.
У каждой учётной записи есть постоянный id и папка профиля
`~/.local/share/RedAnchor/RedAnchor Shell/profiles/<id>/`.

## После настройки

При каждом запуске оболочка спрашивает, кто будет играть: показываются все учётные записи
консоли (или единственная). Затем открывается главный экран: сверху аватар и никнейм,
вкладки **Магазин · Мои игры · Приложения · Библиотека · Настройки** (L1 / R1).
Пока игр, приложений и магазина нет, во вкладках показывается соответствующее сообщение.

Настройки:
- **Сеть** — включение Wi-Fi, подключение к сетям, отключение, состояние кабеля.
- **Bluetooth** — поиск и сопряжение новых устройств, подключение, отключение, удаление.
  Геймпады здесь не показываются. Выключить Bluetooth нельзя: оболочка держит адаптер
  включённым (и включает обратно, если его выключили со стороны), чтобы не отваливались геймпады. Устройства, которым нужен ввод ключа
  (например, клавиатуры), пока не поддерживаются: агент работает без ввода.
- **Пользователи** — добавление локальных пользователей, удаление, смена пользователя.
- **Обновления** — состояние и установка компонентов для игр (см. ниже).
- **Хранилище** — пока недоступно.
- **Геймпады** — переименование, цвет световой панели DualSense, отключение (по Bluetooth).
- **О системе** — версия системы и оболочки, процессор, память, ядро.

При подключении и отключении геймпада сверху по центру появляется уведомление, а при заряде
20, 15, 10 и 5 % — предупреждение о разряде. В строке состояния рядом с часами показывается
значок наушников, если подключена Bluetooth-гарнитура.

### Магазины, библиотека и хранилище

Во вкладке **Магазин** — разделы RedStore (пока в разработке) и GOG; переключение L2 / R2.
Пока фокус в магазине, он раскрывается на весь экран: верхняя строка (аккаунт, время) скрывается,
фон становится однотонным, вкладки и разделы — компактнее.

Загрузчик gogdl для GOG ставится в **Настройки → Обновления**; если его нет, магазин предлагает
установить обновления там.

- **GOG** — gogdl. Вход через встроенный браузер (отдельное окно, Qt WebEngine), управляемый
  геймпадом: крестовина выбирает элементы страницы, ✕ нажимает (на поле ввода — экранная
  клавиатура), △ отправляет форму, ○ — отмена, правый стик — курсор (только в этом окне).

Steam оболочка пока не поддерживает.

У каждого пользователя консоли свои входы в магазины и свои игры — всё лежит в его профиле:
`profiles/<id>/stores/<магазин>/` и `profiles/<id>/games/<магазин>/`. Удаление учётной записи
удаляет и её игры. При смене пользователя загрузки останавливаются.

Поставленная на загрузку игра сразу появляется в **Библиотеке** (с прогрессом) — её уже можно
закрепить на главном экране; во вкладке **Мои игры** закреплённые игры идут рядом крупных
карточек, фоном — широкая картинка выбранной игры. Пока идут загрузки, в строке состояния
виден значок загрузки с прогрессом; загрузок нет — значка нет.

**Хранилище** показывает занятость диска: свои игры, «Остальное» (система, игры других
пользователей и прочее) и свободное место, а также список своих установленных игр с размерами.

Обложки — из SteamGridDB: квадратная обложка, широкий фон и, если есть, видео-обложка WebM.
Ключ API задаётся опцией CMake `REDANCHOR_STEAMGRIDDB_KEY`.

**Поддержка геймпада.** У выбранной в магазине игры видно, поддерживает ли она геймпад
(для GOG — по списку возможностей игры). Если игра официально не поддерживает DualSense,
перед установкой предупреждаем о системе раскладки RedAnchor (управление может быть неточным,
значки — некорректными); если только мышь и клавиатура — что играть на геймпаде не получится.

**Запуск игр** — ✕ в «Моих играх» и библиотеке, меню игры — Options.
- **GOG** — `gogdl launch` с GE-Proton (Настройки → Обновления) в качестве обёртки. У каждой игры
  свой префикс Wine (`profiles/<id>/prefixes/`), вывод — в `profiles/<id>/logs/`.

Игра считается запущенной, пока живы её процессы (лаунчеры часто запускают игру и выходят), —
до этого оболочка показывает фон и название игры; если игра официально не поддерживает
DualSense — рисунок DualSense и предупреждение о системе раскладки. Закрыть игру — PS → игра →
«Закрыть игру» (закрывается и весь сеанс Wine игры).

**Геймпад.** Тачпад DualSense / DualShock 4 система считает мышью — касания двигали бы курсор.
Оболочка забирает тачпад себе, а правило udev (`70-redanchor-dualsense.rules`) скрывает его от
libinput ещё до запуска оболочки. Если после закрытия окна (браузер входа) или обновления
раздела фокус пропадает, оболочка возвращает его сама перед следующим нажатием.

### Компоненты для игр (Ubuntu / Debian)

- **Графический драйвер.** NVIDIA — рекомендуемый драйвер через `ubuntu-drivers`
  (на Debian — `nvidia-driver` из non-free) и его 32-битная часть; заработает после перезагрузки.
  AMD и Intel — Mesa (`libgl1-mesa-dri`, 64 и 32 бита) и прошивки.
- **Vulkan.** `libvulkan1`, `mesa-vulkan-drivers` (64 и 32 бита) и `vulkan-tools`.
- **Системные компоненты.** gamescope (Weston и cage про запас), Xwayland, `libxcb-cursor0`, Python 3
  (на нём написан Proton), PipeWire/WirePlumber, шрифт Inter, BlueZ, NetworkManager, правила
  udev для геймпадов (`steam-devices`).
- **gogdl.** Загрузчик игр GOG — последний выпуск с GitHub,
  в `~/.local/share/RedAnchor/RedAnchor Shell/tools/`.
- **Proton.** Последний GE-Proton с GitHub, проверяется по SHA-512 и распаковывается в
  `~/.local/share/RedAnchor/RedAnchor Shell/compatibilitytools/`; старые версии удаляются.

Системные компоненты, драйверы и Vulkan ставит помощник `redanchor-components` (apt, от root через `pkexec`;
правило polkit `org.redanchor.shell.components` разрешает это активной сессии без пароля),
при необходимости он включает 32-битную архитектуру (`dpkg --add-architecture i386`).
Proton скачивается без прав root.
Если после настройки подключить кабелем новый DualSense (BlueZ ещё не знает его как
сопряжённый), открывается отдельная сцена сопряжения: сопряжение по кабелю → «отключите
кабель и нажмите PS» → подключён по Bluetooth → ✕. ○ закрывает сцену, сопряжение при этом
продолжается в фоне. Уже сопряжённый контроллер на кабеле (например, на зарядке) сцену не открывает.

### Как работает автоматическое сопряжение

Как на консоли: сопряжение происходит по кабелю. BlueZ сам этого для DualSense не умеет
(плагин `sixaxis` знает только DualShock 3/4), поэтому как только DualSense появляется на USB,
оболочка запускает через `pkexec` помощника `redanchor-pair-controller`. Помощник:

1. находит контроллер в `/dev/hidraw*` и читает его MAC;
2. берёт ключ связи из `/var/lib/bluetooth/<адаптер>/<контроллер>/info`, если контроллер уже
   сопрягали с этим адаптером, или создаёт новый;
3. записывает в контроллер адрес адаптера и ключ (feature-отчёт `0x0A`);
4. если ключ новый, сохраняет его в хранилище BlueZ и перезапускает `bluetooth.service`
   (BlueZ читает ключи только при запуске).

После отключения кабеля контроллер по нажатию PS подключается по Bluetooth сам. При первом
таком подключении BlueZ ещё не знает сервисов контроллера, и оболочка вызывает `Device1.Connect`,
чтобы BlueZ его опросил. Дальше всё работает без участия оболочки.

Правило polkit `org.redanchor.shell.pair-controller` разрешает запускать помощника без пароля
пользователю активной локальной сессии. Без установленного правила (запуск из каталога сборки)
`pkexec` попросит пароль администратора.

Диагностика: `journalctl --user -b | grep -i pair` (вывод оболочки) и `journalctl -u bluetooth -b`.

## Управление

| Геймпад      | Клавиатура | Действие                          |
|--------------|------------|-----------------------------------|
| D-pad / стик | стрелки    | навигация                         |
| ✕            | Enter      | выбрать                           |
| ○            | Esc        | назад / закрыть клавиатуру        |
| □            | Backspace  | стереть (клавиатура)              |
| △            | Пробел     | пробел / обновить                 |
| L1 / R1      | PgUp / PgDn| вкладки; Shift / язык (клавиатура)|
| L2           | Home       | символы (клавиатура)              |
| Options      | Menu       | готово (клавиатура)               |
| PS           | Home Page  | подтверждение контроллера         |

Геймпад читается напрямую из `/dev/input/event*` (evdev). Нажатия превращаются
в обычные клавиатурные события, поэтому интерфейс одинаково работает и с мышью/клавиатурой.

## Зависимости и установка

Всё ставится одной командой — от обычного пользователя, права root скрипт попросит через `sudo`:

```sh
./install.sh              # пакеты, драйверы, Qt ≥ 6.10, сборка и установка сессии
./install.sh --deps-only  # только системные пакеты (без Qt из aqtinstall и без сборки)
./install.sh --no-build   # пакеты и Qt, но без сборки
./install.sh --yes        # без вопросов (например, по ssh)
```

Скрипт идёт по шагам `[n/N]` и пишет подробности в `~/.local/state/redanchor/install.log`;
повторный запуск безопасен. Что он делает:

1. Проверяет систему (Ubuntu 24.04+ / Debian 12+, x86_64), включает 32-битную архитектуру
   (`dpkg --add-architecture i386`), доделывает прерванную установку пакетов (`dpkg --configure -a`)
   и ждёт, пока dpkg освободит, например, `unattended-upgrades` (до 10 минут).
2. Ставит инструменты сборки и библиотеки, нужные Qt.
3. Вызывает `data/redanchor-components` с целями `system`, `drivers`, `vulkan` — тот же
   помощник, что ставит компоненты из «Настройки → Обновления». Он сам включает нужные компоненты
   репозиториев (universe/multiverse в Ubuntu, contrib/non-free в Debian; PPA и чужие репозитории не трогает,
   копии файлов источников — в `/var/backups/redanchor/`) и пропускает пакеты, которых нет в дистрибутиве.
4. Ищет Qt ≥ 6.10: `QT_PREFIX`, затем `~/Qt/<версия>/gcc_64` (онлайн-установщик или aqtinstall),
   затем системный Qt. В репозиториях Ubuntu 24.04 — Qt 6.4, в Debian 13 — 6.8, этого мало: скрипт
   предложит поставить Qt через [aqtinstall](https://github.com/miurahr/aqtinstall) в `~/Qt`
   (окружение Python — в `~/.local/share/redanchor-aqt`). Версия по умолчанию — 6.10.1,
   другая: `QT_VERSION=6.11.0 ./install.sh`. Готовый Qt: `QT_PREFIX=~/Qt/6.12.0/gcc_64 ./install.sh`.
5. Собирает (`build-release/`) и ставит оболочку (`sudo cmake --install`), перечитывает правила udev,
   включает загрузку модуля `uinput` и добавляет пользователя в группу `input`.

Proton (GE-Proton) и gogdl ставятся не скриптом, а самой оболочкой без прав root — на шаге мастера
«Проверка обновлений» или в «Настройки → Обновления». Qt из `~/Qt` доступен только вашему
пользователю: если сессией будут пользоваться другие учётные записи Linux, поставьте Qt в общий
каталог (`QT_INSTALL_DIR=/opt/Qt`, каталог должен быть доступен на запись) или используйте системный Qt.

## Сборка и запуск

```sh
cmake -B build -DCMAKE_PREFIX_PATH=~/Qt/6.12.0/gcc_64
cmake --build build
./build/redanchor-shell --reset-setup    # для разработки: пройти мастер заново
./build/redanchor-shell --fullscreen     # как в сессии
```

Используются только настоящие службы: если BlueZ не запущен или нет адаптера,
оболочка считает, что Bluetooth-модуля нет; если нет Wi-Fi устройства — что Wi-Fi модуля нет.
Адаптеры, подключённые на ходу (например, USB-донглы), подхватываются автоматически.

## Установка как сессии

```sh
sudo cmake --install build
```

Команда установит `redanchor-shell`, `redanchor-session`, `/usr/share/wayland-sessions/redanchor.desktop`,
помощников `libexec/redanchor-pair-controller` и `libexec/redanchor-components`, правила polkit для них
(`/usr/share/polkit-1/actions`) и правило udev для световой панели DualSense
(`/usr/lib/udev/rules.d/70-redanchor-dualsense.rules`). Эти два каталога системные и не зависят
от префикса установки — polkit и udev читают правила только оттуда. После установки правила
udev переподключите геймпад (или выполните `sudo udevadm control --reload`).
После этого в менеджере входа (GDM и т.п.) появится сессия **RedAnchor**. Скрипт сессии
запускает оболочку в `gamescope` (если он установлен) или в `cage`; если gamescope не смог
запуститься, сам пробует cage. Принудительно выбрать композитор: `REDANCHOR_COMPOSITOR=cage`.

Если после входа сразу возвращает на экран входа — смотрите журнал сессии
`~/.local/state/redanchor/session.log`. Частые причины:
- оболочке не хватает библиотек Qt (собрано с Qt из `~/Qt` до того, как в установку добавили путь к нему — пересоберите и установите заново);
- нет `libxcb-cursor0` — без него Qt не запускается внутри gamescope (`sudo apt install libxcb-cursor0`);
- экран входа работает на Xorg (`WaylandEnable=false` в `/etc/gdm3/custom.conf`, часто с NVIDIA) — тогда сессии Wayland в списке не показываются.

Права доступа:
- **Геймпады.** logind выдаёт доступ к джойстикам активной сессии (тег `uaccess`). Если доступа нет, добавьте пользователя в группу `input`.
- **Bluetooth.** Нужен доступ к `org.bluez`. Если `RegisterAgent` или `Pair` отклоняются, добавьте пользователя в группу `bluetooth`.
- **Сеть.** Нужен доступ к NetworkManager. polkit разрешает его пользователю активной локальной сессии.
- **Система раскладки (виртуальный контроллер Xbox).** Нужен доступ к `/dev/uinput`; правило udev оболочки выдаёт его пользователю активной сессии. После установки правила выполните `sudo udevadm control --reload && sudo udevadm trigger` или перезагрузитесь.
- **Питание из оверлея.** Перезагрузка и выключение идут через logind; пользователю активной локальной сессии они разрешены без пароля.
- **Цвет DualSense.** Файлы светодиода в `/sys/class/leds` по умолчанию доступны только root;
  правило udev оболочки открывает их на запись.

## Структура

```
src/        C++: GamepadManager (evdev), BluetoothManager (BlueZ D-Bus),
            StoreManager (магазины),
            GameLibrary (игры пользователя), GameLauncher (запуск), GameArt (SteamGridDB),
            NetworkBackend (NetworkManager D-Bus), AccountManager (учётные записи),
            SystemInfo (сведения о системе)
src/pairhelper/  помощник сопряжения DualSense по кабелю (root, через pkexec)
data/       правило polkit для помощника, правило udev для световой панели
qml/        Main.qml, Theme (палитра/масштаб), Keyboard (мост к экранной клавиатуре)
qml/components/  DualSense, UsbCable, OnScreenKeyboard, кнопки, списки, поля…
qml/setup/  экраны мастера настройки
qml/home/   выбор пользователя, главный экран, настройки (qml/home/settings/)
session/    скрипт и .desktop-файл сессии
```
